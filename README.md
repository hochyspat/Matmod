# Приближённые алгоритмы для многоэшелонного управления запасами

Учебный исследовательский проект по математическому моделированию. Цель — реализовать точный и приближённый методы планирования поставок и сравнить стоимость решений и время вычислений на синтетических данных.

## Постановка
Рассматривается двухэшелонная последовательная система: внешний поставщик снабжает центральный склад, склад снабжает магазин. Требуется определить моменты и объёмы поставок при известном спросе и ограниченной вместимости, минимизируя расходы на оформление заказов и хранение.

Рабочая модель использует конечный дискретный горизонт, целочисленные объёмы и отсутствие дефицита. Порядок событий и формулы приведены в [описании модели](docs/model.md). Для основной серии приняты постоянный спрос и нулевые начальные и конечные запасы. Версия модели фиксируется в данных.

## Соответствие заданию
| Требование | Принятое решение и запланированный результат |
|---|---|
| Два или три эшелона | Два эшелона: центральный склад и магазин |
| Заданный спрос и ограниченная ёмкость | Постоянный известный спрос и ограниченная вместимость обоих узлов |
| Время и объёмы поставок | Объёмы внешних заказов и перемещений по периодам; нулевой объём означает отсутствие поставки |
| ДП для двухэшелонной последовательной системы | Точный решатель дискретной модели с восстановлением плана |
| Приближённый алгоритм | Исходный Roundy как теоретическая основа и метод, учитывающий ограничения общей модели |
| Сравнение на синтетических данных | Допустимость, отклонение от оптимума на малых задачах и время работы |
| Программный комплекс и сравнительный анализ | Общий запуск, воспроизводимые эксперименты и отчёт |

Таблица описывает направление реализации. Фактически готовые компоненты перечислены ниже; точный и приближённый решатели пока не реализованы.

## Запуск
Нужен Python 3.10 или новее. Текущая реализация использует только стандартную библиотеку.

Из корня репозитория:

```bash
python run.py instances/01_basic.json
python run.py instances/02_tight_capacity.json
python run.py instances/03_infeasible.json
```

Если в системе используется команда `python3`, замените ею `python`.

Без дополнительных параметров программа выводит условия и проверяет структуру JSON. Недопустимая математическая задача может иметь корректную структуру данных: третий пример должен успешно загружаться. Поиск решений пока не реализован.

Проверка готового плана:

```bash
python run.py instances/01_basic.json --plan examples/01_basic_plan.json
python run.py instances/02_tight_capacity.json --plan examples/02_tight_capacity_plan.json
python -m unittest discover -s tests -v
```

Независимо пересчитываются запасы и стоимость. Подробности и пример ошибочного плана приведены в [описании проверки](docs/validation.md).

## План развития
1. Развивать реализованную независимую проверку при появлении новых алгоритмов и контрольных случаев.
2. Реализовать ДП с восстановлением решения; проверить его на малых задачах.
3. Воспроизвести исходный алгоритм Roundy и разработать адаптацию к общей модели сравнения.
4. Подготовить генератор экземпляров, измерение качества и времени, сравнительный анализ и отчёт.

Новые модули и каталоги добавляются по мере реализации. Для будущих алгоритмов пока не создаются фиктивные решатели или пустые результаты экспериментов.

## Принципы сравнения
Оба метода должны получать одинаковые спрос, ёмкости, горизонт, начальные и конечные условия. Допустимость и стоимость планов проверяются независимо. Отклонение от оптимума измеряется только там, где точный метод завершил решение; превышение нижней оценки указывается отдельно.

Исходный метод Roundy относится к постоянному спросу, непрерывному времени и бесконечному горизонту без ограничений ёмкости. Гарантия 98% не переносится автоматически на дискретную адаптацию с ёмкостями. Проверки исходного метода и сравнение адаптации с ДП разделяются.
