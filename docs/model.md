# Математическая модель

Рабочая постановка проекта `serial_inventory_v1`. Ниже зафиксированы выбранные допущения для реализации и сравнения методов. Контрольные примеры соответствуют этой версии.

## Принятые допущения
1. Один товар, один центральный склад, один магазин. Внешний поставщик вне системы.
2. Конечный горизонт из H периодов; индекс в файле начинается с 0, в объяснениях — с 1.
3. Основной случай — постоянный известный спрос: d единиц в каждом периоде. Массив спроса в формате данных оставлен для возможного расширения; переменный спрос не входит в основную серию экспериментов.
4. Количества целочисленные, неотрицательные. Пересортицы и потерь нет.
5. Поставка мгновенная. Не более одного внешнего пополнения и одного перемещения в период.
6. Ёмкости ограничивают физический запас каждого узла. Ограничений мощности поставщика и транспорта пока нет.
7. Дефицит запрещён, списание товара запрещено.
8. Положительный внешний заказ оплачивается фиксированной стоимостью склада; положительное перемещение — фиксированной стоимостью магазина.
9. Хранение оплачивается по остатку в конце периода. Это дискретная целевая функция, не непрерывная средняя стоимость Roundy.
10. В основной серии начальные и конечные запасы обоих узлов равны нулю. Поля формата допускают явное задание иных запасов для будущих расширений; такие экземпляры должны рассматриваться отдельно.

## Порядок событий
Пусть W и R — запасы на начало периода, q — внешняя поставка, x — перемещение в магазин, d — спрос.
1. Приходит q: проверяем 0 ≤ W + q ≤ Cw.
2. Отгружается x: проверяем 0 ≤ x ≤ W + q и R + x ≤ Cr.
3. Выполняется спрос: проверяем R + x ≥ d.
4. Остатки: W_next = W + q − x; R_next = R + x − d.
5. Начисляем затраты: Kw при q > 0, Kr при x > 0, плюс hw × W_next + hr × R_next.

Ёмкость склада проверяется ДО отправки в магазин, ёмкость магазина — ДО спроса. Поэтому большой транзитный объём нельзя скрыть нулевым конечным запасом. Смена порядка событий меняет задачу и допустимость примеров.

## Единицы
Количество — условные единицы товара. Время — период. Фиксированные затраты — денежные единицы за заказ, хранение — денежные единицы за единицу остатка за период. Входные ставки не нормированы к спросу 2. Нормировка для исходной модели Roundy должна выполняться отдельно.

## Целевая функция
Минимизируется сумма затрат всех H периодов. Фиксированная стоимость возникает только при положительном объёме соответствующего заказа. Хранение оплачивается по конечному остатку каждого периода, включая последний; в основной серии последний остаток равен нулю.

## Область применения
Модель конкретизирует постановку задания: два эшелона, известный спрос, ограниченная вместимость и выбор времени и объёмов поставок. Трёхэшелонные сети, переменный спрос, ненулевые сроки доставки и ограничения мощности не входят в базовую реализацию.

Исходная статья Roundy использует другую модель: непрерывное время, бесконечный горизонт и отсутствие ограничений ёмкости. Алгоритм статьи воспроизводится отдельно, а его адаптация должна возвращать допустимый план настоящей модели. Гарантия 98% для такой адаптации не предполагается без отдельного доказательства. Экспериментальное сравнение проводится с точным ДП на одинаковых входных данных.

## Изменение постановки
При расширении модели изменяются её идентификатор, документация, контрольные примеры и затронутые реализации. Существующий идентификатор не используется для другого порядка событий или другой целевой функции.
